Feelings to Numbers

step8_evaluation.py stops eyeballing printed chunks and scores everything: a 6-question hand-labeled golden set, three retrieval metrics (MRR, Hit@k, Precision@k), and two LLM-judged answer metrics (Faithfulness, Relevance) — run across all four chunking strategies from step 7. Every number below is real output from one run.

Three metrics, four strategies — one of them is lying to you

evaluate_retrieval() runs the same 6 golden questions against each strategy's index with k=3. Hit@3 says every strategy is perfect. MRR and Precision@3 say otherwise.

Cheap filter first, expensive judge only on the winner

reciprocal_rank() is a substring check — free. Faithfulness and Relevance need a second LLM call per question — 18 calls total. So only the strategy that already won on MRR pays for that.

The judge doesn't agree with itself

Part C re-runs generation and judging per question — a second, independent pass over the exact same 6 questions, same strategy, same judge model that Part B already scored.

Worth noticing, not yet proving Question 1's answer reads as completely grounded — it restates exactly what the retrieved chunk says — yet the judge scored it Faithfulness = 0.00 in Part C while Part B's separate pass, averaged across all six questions, landed at 0.42. Both numbers came from the same model (llama3.2:3b) generating the answer and judging it — the exact blind spot the guide sheet names: a model's failure modes in generation can correlate with its failure modes in judging its own output, and re-running the identical pipeline doesn't even reproduce the same score twice. And expected_phrase is hand-tied to this exact document's wording — edit DOCUMENT in step 7 without updating GOLDEN here, and every retrieval metric silently reads as failure for no real reason. Step 9 — Reranking adds a second scoring pass over retrieval itself — not to fix the judge, but because bi-encoder cosine similarity, scored here as ground truth, has its own blind spots worth measuring against something else.
